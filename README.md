# 节能证据与验收

本地合成业务资料。人名标识、去向、机构和观测均为虚构，不接入外部系统。

## 输入约定

`data/supplies.json` 以表名组织记录；`data/fields.json` 列出字段及该资料出现的值类型。

`reading` 是当日供热用量而非累计表底，单位千瓦时；总表与分表覆盖不能重复。`degree_days` 和 `open_hours` 是同日期的有效天气与营业观测。`weather.split` 为预先备案的拟合、留出或改造后窗口；允许模型选择但不许将留出或改造后的结果用于训练。适用窗口按 `protocol` 中温度日度、开放时长和测点覆盖判断，未测部分不能假作零；总表和分表可以只约束可归属节能区间。舒适记录为开放时间内最低温度，既有签认是可核验业务事实。`maintenance.action` 为比例换算或撤销，`from`、`until` 均包含端点；仅影响命中的读数，资料按 `recorded` 才可使用。
合同分别按用途验收，不得互抵。阶段签认要求合同证据范围下界不低于规定节能量、适用覆盖达标且开放的已测时间内符合最低舒适度；舒适缺测未满足合同覆盖则待补证。可提请指定可观察的开放时段补测，不从停用时段生成有效基准；签认卷宗以 `signed_at` 对照当时事实。

## 资料检查

在 Linux 上使用 Python 3.11 及标准库，无需安装第三方包。运行 `python3 -m unittest discover -s tests -v` 检查表字段、类型和关键关联。当前仓库只包含业务来源资料及检查，尚无分析结果或业务操作入口。
