# 节能证据与验收

本地合成业务资料。人名标识、去向、机构和观测均为虚构，不接入外部系统。

## 输入约定

`data/supplies.json` 以表名组织记录；`data/fields.json` 列出字段及该资料出现的值类型。

`reading` 是当日供热用量而非累计表底，单位千瓦时；`meter_map` 中分表按用途独立计量，总表还涵盖未分项的管路等耗热。`degree_days` 为同日期采暖度日，`activity` 中记录实际开放小时和当日开放期间的最低室温（摄氏度）。`calendar` 同时给出承诺开放小时与实开小时：临时停用不消除最初的开放承诺，计划停用则无该承诺。`weather.split` 是预先备案的拟合、留出、分步投用及全部投用后日期；分步期只有未投用的用途可用独立分表作额外基准证据，不划入备案留出样本。日粒度记录在翌日可知。
`maintenance.action` 为比例换算或撤销，`from`、`until` 均包含端点；每个表的每个日期按截至查询日最近发布的有标记更正解释。换算系数相对原读数而不是相对上一次结果。当日总表和有效分表合计差异超出 `meter_tolerance_kwh` 且无法由非负的未分项用热解释时，不能用总表联合归属；对独立分表的采信用各自校准证据判断。
合同分别按用途验收，`effective` 为首个改造已投用日，`max_holdout_mae_kwh` 是采用相应基准时留出预测的平均绝对误差上限。`min_saving` 是申请阶段的累计千瓦时节能下限。覆盖率分母是申请阶段、改造已投用、承诺开放且在 `degree_days_range` 和 `hours_range` 约定内的日期数（小时范围用承诺开放时间）；分子须有可采用的耗热证据、有基准支撑并且温度可核。计划停用不在分母；临时停用仍是缺口。共有证据若不能支持每份合同的独立额度，不靠合同之间抵扣。`rate_yuan_per_kwh` 供审签材料解释计价依据，不触发实际付款。签认卷宗以 `basis_date` 对照可知事实，以 `signed_at` 标记已确认时间。

## 资料检查

在 Linux 上使用 Python 3.11 及标准库，无需安装第三方包。运行 `python3 -m unittest discover -s tests -v` 检查表字段、类型和关键关联，并锁定分析口径的关键不变量（更正生效时点、留出不进拟合、覆盖率与归属上限等）。

## 验收分析

`python3 -m analysis` 生成验收会报告（默认查询日 2026-11-19，输出到 `out/report_<查询日>.md` 与同名 `.json`）：

```
python3 -m analysis --query-date 2026-11-19 --data data/supplies.json --out out
```

口径要点：日粒度记录翌日可知，更正按发布日截至查询日生效（换算相对原读数、撤销置无效）；基准只用备案拟合窗（X1 另加分步投用期 M1 独立证据），留出窗只核对不进拟合；合同节能只在约定度日/小时范围内签认，不外推；室温缺测不是温度合格，挡当日节能；各合同当日可签合计不超过总表节能，超出部分不互抵、列为未归属缺口；查询日之后发布的更正（如 2026-11-20 的 M1 留出撤销）不纳入主口径，只在报告附录提示重跑。报告含分用途、总表、分合同节能范围，已签/待签卷宗的旧依据对照，以及独立计量、可比基准、开放期温度证据三类缺口清单。
